# Защита от АФК — «темп-монитор» (v0.1, по твоей формулировке)

## Постановка (из ТЗ)
Замеряем обычный темп человека. Если текущее задание выполняется **в ≥10 раз медленнее**
обычного для подобного типа — это АФК: заданию даётся вес = среднему времени на подобное,
а **фактическое (пауза-раздутое) число в среднее НЕ попадает**.

## Определения
- `task_kind` — тип задания (см. SESSIONS.md): CHOICE_R2T, TYPE_XX2EN, LISTEN_CHOOSE, SPEAK_REPEAT…
- `active_ms(task)` — активное время: интервалы фокуса минус куски простоя длиннее
  `IDLE_CUT=25с` (экран открыт, но человек пинал балду — разрыв вычитается).
- `pace_stats[kind]` — скользящее окно N=30 «чистых» выполнений kind'а (только не-AFK).

## Алгоритм (эталон: shared/algorithm/reference.py::judge_task)
```
1. Задание началось → журнал событий (input / focus_out / focus_in) пишется компактно.
2. active_ms > PACE_LIMIT = max(10 × median(pace_stats[kind]), MICRO_FLOOR=120с)
   → afk_suspect=true. Если чистых замеров < 5 — порог = CEILING 10 мин
   (не бракуем статистику новичков).
3. Завершение:
   a) чисто: weight_ms = active_ms; результат SRS как есть; active_ms ДОБАВЛЯЕТСЯ в pace_stats.
   b) afk_suspect: weight_ms = median(pace_stats);  ← «вес по среднему»
      active_ms в pace_stats НЕ добавляется;         ← «новое число не вносим»
      попытка afk_excluded=true: SRS её не видит (карточка вернётся в очередь без штрафа),
      но дневной прогресс получает weight_ms, а оценка урока режется (SCORING §D).
4. effective_session_ms = Σ weight_ms (НЕ wall-clock!). В бюджет минут и синхронизацию
   идёт именно оно. Час с 59-ю минутами простоя = 6 честных минут.
```

## Дополнительно к твоему правилу (предлагаю, на ревью)
- idle > 90с → затемнение экрана с драконом-соней (`dragon_sleep.png`) «Дракон ждёт».
- Античит-автокликер: ≥8 вводов с коэффициентом вариации меж-интервальных расстояний <0.15 → тоже suspect.
- Все константы (PING_WINDOW, IDLE_CUT, ×10, N=30, CEILING, FLOOR) — общие для Kotlin/C++/Python, сверяются фикстурами.
- Сервер хранит копию (kind, active_ms, weight_ms, suspect) в `pace_aggregate` — аудит + v2 калибровка порога.
