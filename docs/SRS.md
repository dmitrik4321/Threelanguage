# Алгоритм интервального повторения — FSRS-lite (v0.1, подробно, для ревью)

## Почему не SM-2
SM-2 (классический Anki 2.1): одно число EF, жёсткая формула, плохо переносит «почти знал»,
не различает сложность карточки и стабильность памяти. Для трёх языков с очень разной
плотностью материала (EN vs ZH) нужен двухмерный профиль памяти. Берём **FSRS**
(Free Spaced Repetition Scheduler, открытая модель, MIT) в упрощённой форме —
«FSRS-lite»: те же состояния карточки, но фиксированные параметры модели вместо
персональной дообучаемой кривойзабывания (дообучение на сервере по агрегированной статистике — v2).

## Состояние карточки (хранится в card_states)
| Поле | Тип | Смысл |
|---|---|---|
| `stability` S | float, дни | насколько долго память устойчива (1/e вероятность вспомнить через S дней) |
| `difficulty` D | 1..10 | внутренняя сложность карточки |
| `due` | timestamp | когда показать снова |
| `reps`, `lapses` | int | счётчики |
| `state` | enum | New / Learning / Review / Relearn |

## Грейды ответа (4 уровня, генерируются скорингом урока, см. SCORING.md)
`Again(1)` — не вспомнил; `Hard(2)`; `Good(3)`; `Easy(4)`.
Скоринг переводит непрерывную оценку задания в грейдж: <45→Again, 45–69→Hard, 70–89→Good, ≥90→Easy.

## Формулы (эталон — shared/algorithm/reference.py)
Модель забывания: `retention(t) = exp(-t * ln(0.9) / S)`  (через S дней — 90% вероятности вспомнить при t=S).

Параметры (дефолты, все настраиваемые одним dict — подгоним под CJK отдельно):
```
w = [0.4, 1.4, 3.2, 15.2,        # начальные S для Again..Easy (new card)
     6.6, 0.9, 2.05, 0.05,       # влияние D и S при Again(lapse)
     1.15, 0.15, 1.8,            # множители Hard/Good/Easy при recall
     0.15]                       # флеш-буст после обучения
desired_retention = 0.90         # целевая задержки (настройка пользователя 0.80–0.95)
```

### Новая карточка (state=New), первый ответ G∈{1..4}
```
S0(G) = w[G-1]                                  # 0.4 / 1.4 / 3.2 / 15.2 дня
D0(G) = clamp(w[4] - (G-3), 1, 10)              # Easy снижает сложность, Again повышает
```

### Повтор (recall, G∈{2,3,4}) — карточка была в due
```
hard  = w[5] (=6.6 → нормализуем: множитель Hard)   # фактически m_hard=w[6]=0.9? — фиксируем читаемо:
m(Hard)=0.9, m(Good)=1.0, m(Easy)=1.8               # из w[6..8]-подобных
S' = S * (1 + exp(w[9]) * (11-D) * S^(-w[10]) * (exp((1-R)*w[11]) - 1) * m(G))
```
Упрощённая форма, которую реализует reference.py (все константы в одном словаре,
значения — дефолты FSRS-4.5, усечённые до 13 параметров):
```
R = retention(elapsed, S)                        # фактическая задержка в момент ответа
D' = clamp(D - 0.2*(G-3) + 0.1, 1, 10)           # difficulty дрейфует от оценки
S'_recall = S * (1 + e^(a) * (11-D') * S^-b * (e^(c*(1-R)) - 1) * mult(G))
   a=0.1, b=0.15, c=0.9; mult = {Hard:0.6, Good:1.0, Easy:1.6}
```

### Забыл (G=Again, state=Review) — lapse
```
S'_relearn = w[5] * D^-w[6] * ((S+1)^w[7] - 1) * exp((1-R)*w[8])
   w[5]=0.5, w[6]=0.4, w[7]=0.6, w=0.65→w[8]=0.65
D' = min(D + 1, 10)
карточка уходит в Relearn: шаги 10 мин → 1 день → возврат в Review
```

### Назначение due
```
interval_days = S * (desired_retention^(1/ln(0.9)) ... )  → упрощённо:
t = -S * ln(desired_retention) / ln(0.9)   # из model forgetting: R(t)=0.9^(t/S)... 
реализация: t = S * log(desired)/log(0.9)? — эталон задаёт t такой, что retention(t)=desired:
t = S * (-ln(desired) / -ln(0.9)) = S * ln(desired)/ln(0.9)
для desired=0.9 → t = S (ровно). Cap: 365 дней. Learning-steps: Again→10min, Hard→1d*0.5.
```

### Short-term (Learning/Relearn)
Пока карточка в Learning, S обновляется простой схемой: успешный шаг ×2.2, ошибка сброс на step 0.
Выход в Review после последнего шага с Good+.

## Интеграция с АФК (важно!)
Попытка, помеченная `afk_suspect=true` (см. AFK.md), **не влияет на S/D**: карточке
назначается вес = медиане времени на подобные задания, а её результат считается только
для прогресс-бара дня, но не для SRS. Это ровно твоя формулировка «вес по среднему, новое число в среднее не вносим» — детали в AFK.md.

## Настройки пользователя
- `desired_retention` 0.80–0.95 (по умолчанию 0.90; ниже = чаще показывать = быстрее долбёжка).
- Отдельные веса сложности языка: для CJK D стартует +1 (иероглифы объективно тяжелее на старте), параметр языка в таблице courses.

## Валидация алгоритма
`shared/algorithm/fixtures/srs_cases.json` — набор входов (состояние+грейд+elapsed) → ожидаемые S/D/due
с допуском 1e-6. Прогоняется Python-референсом, Kotlin-тестом и C++-тестом на CI. Расхождение = баг.
