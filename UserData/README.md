# UserData — журнал прогресса по словам

Папка `UserData/` (создаётся сервером автоматически, в git не попадает).
На каждого пользователя — свой файл `<username>.json`.

## Зачем
`states` в SQLite — это слепок клиента с конкретного устройства.
UserData — накопительный человекочитаемый журнал: его можно открыть глазами,
отдать тренеру, сравнить с другого устройства. Пишется при каждом успешном
`POST /api/sync/push` (best effort: ошибка журнала не ломает синхронизацию).

## Формат файла
```json
{
  "username": "anna",
  "updated_at": 1730490000,
  "words": {
    "<stable_id карточки>": {
      "text": {"en": "She wants water.", "pt-BR": "Ela quer água."},
      "langs": ["en", "pt-BR"],
      "asks": 5,
      "errors": 2,
      "last_correct": true
    }
  }
}
```
- `asks` — сколько раз карточку спрашивали (по репетициям SRS-стейта);
- `errors` — сколько раз ошибались (лапсы);
- `last_correct` — последний ответ верно (grade >= 3) / неверно;
- `known`: слово считается известным, если asks >= 2 и errors*3 <= asks
  (эвристика журнала; решение о повторении принимает ядро FSRS-lite, не журнал).

## Изоляция/безопасность
Путь переопределяется env `TL_USERDATA_DIR` (тесты используют свой HOME).
Имя файла санитизируется (только [a-z0-9_-]). Чтение битого JSON не роняет
сервер — журнал просто начинается заново.
